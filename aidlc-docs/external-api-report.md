## 2. 한국관광공사 TourAPI 🔴

### 무엇을 하나

앱에 나오는 **장소 정보 전부**가 여기서 옵니다. 우리 서버에는 장소 데이터가 없고, 사용자가 화면을 열 때마다 관광공사에 실시간으로 물어봅니다.

| 앱 화면 | 받아오는 것 |
|---|---|
| 지역별 장소 목록 | 이름 · 주소 · 좌표 · 사진 · 분류 |
| 검색 결과 | 〃 |
| 주변 장소(반경) | 〃 + 거리 |
| 장소 상세 | 위 + 소개글 · 전화번호 · 홈페이지 |
| **영업시간** | 장소별로 **한 건씩 따로** 조회 |

### 데이터 규모 (실측)

| 범위 | 장소 수 |
|---|---|
| 군산 | 333곳 |
| 전주 | 471곳 |
| **서비스 지역 합계** | **804곳** |
| (참고) 전북 전체 | 2,425곳 |
| (참고) 전국 | 49,722곳 |

검색·주변 조회는 지역 밖 장소도 가져올 수 있어, 실제로 다루는 장소는 804곳보다 늘어날 수 있습니다.

### 💰 비용과 한도 — **결정 필요**

**무료지만 하루 호출 횟수에 한도**가 있습니다. 현재 **개발용 계정**으로 보이며 **일일 약 1,000회** 수준입니다.

문제는 **영업시간**입니다. 관광공사는 영업시간을 목록으로 주지 않고 **장소 하나당 한 번씩** 물어봐야 합니다.

```
군산·전주 전체 장소의 영업시간을 채우려면  →  약 800회
개발계정 하루 한도                        →  약 1,000회
```

즉 **영업시간을 처음 채우는 것만으로 하루치를 거의 다 씁니다.**

**→ 이미 조치한 것**: 한 번 받은 영업시간을 우리 DB에 영구 보관하도록 바꿨습니다.
초기 적재(약 800회)만 끝나면 이후에는 신규 장소분만 호출하므로 **평소 사용량은 거의 0**이 됩니다.

**→ 확인 필요**: 공공데이터포털 마이페이지에서 **실제 일일 트래픽 수치**를 확인해 주세요.
운영계정으로 전환하면 한도가 크게 늘어 여유가 생깁니다(전환은 무료, 신청 절차만 필요).

| 계정 | 일일 한도 | 우리 상황 |
|---|---|---|
| 개발계정(현재 추정) | 약 1,000회 | 초기 적재 시 빠듯함 |
| 운영계정 | 훨씬 큼 | 여유 |

### ⚠️ 서비스 리스크

**① 관광공사가 멈추면 장소 기능이 전부 멈춥니다**

우리가 장소 데이터를 갖고 있지 않기 때문입니다. 다만 최근 조치로 **영업시간은 우리 DB에 있어 관광공사가 죽어도 남아 있습니다.**
코스·러닝 기록·업적은 우리 DB라 영향 없습니다.

**② 데이터 품질은 관광공사에 달려 있습니다**

우리가 고칠 수 없는 부분입니다. 실제로 겪은 사례:

- **전주 장소가 0건이었음** — 관광공사에 "전주시" 단위 데이터가 없고 완산구·덕진구로 나뉘어 있었습니다. (✅ 수정 완료, 현재 정상)
- **영업시간 표기가 제각각** — `- 12:00~21:00- 준비시간 14:00~17:00` 처럼 구분 없이 붙어 옵니다. (✅ 서버에서 정리해 앱에 전달)
- **영업시간이 아예 없는 장소도 있음** — 원천에 없으면 방법이 없습니다. 앱에서는 빈칸으로 표시됩니다.

**③ 없는 데이터: 편의시설**

관광공사에는 **화장실·편의점 분류가 아예 없습니다.** 현재 제공 가능한 분류는 아래 뿐입니다.

```
관광지 · 음식점 · 카페 · 문화시설 · 축제 · 레포츠 · 숙박 · 쇼핑 · 여행코스
```

편의시설이 필요하면 **별도 데이터 확보가 필요합니다**(4번 항목 참고).

## 3. 카카오·애플 로그인 🟢

### 무엇을 하나

사용자가 소셜 로그인을 누르면, 앱이 받은 인증 정보를 **서버가 진짜인지 확인**하는 용도로만 사용합니다.

- **카카오**: 카카오에 문의해 사용자 식별번호와 닉네임을 받습니다
- **애플**: 애플 공개키로 인증 정보를 검증합니다. **애플은 닉네임을 주지 않아** 자동 생성합니다

### 비용·한도

**둘 다 무료이고 호출 한도가 없습니다.** 로그인할 때 한 번씩만 부르므로 사용량도 미미합니다. 관리할 것이 없습니다.

### 🔒 수집하는 개인정보 — **확인 필요**

현재 **최소한만 수집**하고 있습니다.

| 항목 | 수집 | 출처 |
|---|---|---|
| 소셜 식별번호 | ✅ | 카카오/애플 |
| 닉네임 | ✅ | 카카오 (애플은 자동생성) |
| 성별 · 키 · 몸무게 | ✅ | **사용자가 온보딩에서 직접 입력** |
| **이메일** | ❌ **수집 안 함** | — |
| 전화번호 · 생년월일 · 실명 | ❌ 수집 안 함 | — |

카카오가 이메일을 줄 수 있지만 **받지 않고 버리고 있습니다.** 개인정보 처리방침이 단순해지는 장점이 있습니다.

**다만 이메일이 없어서 못 하는 것이 있습니다:**

- **계정 복구 불가** — 소셜 계정을 잃으면 러닝 기록·업적도 함께 잃습니다. 대체 확인 수단이 없습니다
- 이메일 공지·마케팅 발송 불가
- 고객 문의 시 본인 확인 수단 없음

> ⚠️ **나중에 추가하기 어렵습니다.** 카카오는 동의 항목 추가 후 **기존 사용자 전원 재동의**가 필요하고,
> 애플은 **첫 로그인 때만 이메일을 주기 때문에** 이미 가입한 사용자의 이메일은 사실상 받을 수 없습니다.
> **이메일이 필요하다면 초기에 결정하는 편이 훨씬 유리합니다.**

## 4. 편의시설(화장실·편의점) — 미구현

기획상 필요하다면 별도 작업이 필요합니다.

| 항목 | 현황 |
|---|---|
| **공중화장실** | 공공데이터 확보 완료 (군산 445 + 전주 273 = **718건**) |
| | ⚠️ 단, **위경도 좌표가 없고 주소만 있음** → 지도 표시·주변 검색 불가 |
| | → 주소를 좌표로 바꾸는 작업(1회) 필요. 무료 API로 가능 |
| **편의점** | **데이터 없음.** 관광공사에도 없음 |
| | → 소상공인시장진흥공단 상가정보 등 별도 확보 필요(좌표 포함되어 있음) |

두 항목 모두 **한 번 확보해 우리 DB에 넣으면 되므로 TourAPI 한도와 무관**합니다.

## 6. 개발팀이 이미 조치한 것

참고용입니다. 별도 확인은 필요 없습니다.

- ✅ **영업시간 DB 영구 보관** — 매일 반복되던 호출을 없애 한도 문제를 크게 완화
- ✅ **전주 장소 0건 결함 수정** — 완산구·덕진구를 합쳐 조회하도록 변경 (0건 → 318건)
- ✅ **영업시간 표기 정리** — 관광공사 원문을 앱이 바로 쓸 수 있는 형태로 가공
- ✅ **장애 대비** — 관광공사 응답이 느리거나 실패해도 앱이 멈추지 않고, 해당 정보만 비워서 정상 응답
- ✅ **호출 속도 제한** — 관광공사의 초당 제한을 넘지 않도록 자동 조절
