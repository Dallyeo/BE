# 업적 13종 추가 — 기준 입력 시트

> **작성 이유**: 디자인 시안(`src/main/resources/data/list1~3.png`)에는 업적이 **21종**인데
> 서버 카탈로그(`AchievementType`)는 **8종**입니다. 나머지 13종을 추가하려면 임계값·판정 기준을
> 정해야 하는데, 시안에 안 적힌 게 있어(예: 뚜벅이 "키로당 몇 분") 임의로 정할 수 없습니다.
>
> **사용법**: 각 항목의 `[답]:` 뒤에 적어주세요. 제안값이 괜찮으면 **`그대로`** 라고만 쓰면 됩니다.
> 전부 채울 필요 없고, 정한 것부터 구현하겠습니다. 보류할 항목은 `보류` 라고 적어주세요.

## 0. 먼저 알아야 할 것 — 서버가 러닝에 대해 아는 정보

판정은 아래 값들로만 가능합니다. 이 목록에 없는 건 **앱이 추가로 보내주거나, 판정 방식을 바꿔야** 합니다.

| 저장되는 값 | 설명 |
|---|---|
| `courseId` | 시드(공식) 코스를 달렸으면 코스 id, 자유 러닝이면 `null` |
| `distanceMeters` | 이번 러닝 거리 |
| `durationSeconds` | 이번 러닝 소요 시간 |
| `averagePaceSeconds` | 평균 페이스(초/km) |
| `startedAt` / `finishedAt` | 시작·종료 시각 |
| `polyline` | 실제 달린 좌표 배열 |

**서버가 모르는 것**: 도착지로 어떤 장소를 골랐는지, 사용자가 만든 코스의 경유지가 몇 개인지,
특정 장소를 "방문"했는지. (사용자가 직접 만든 코스는 백엔드에 저장하지 않습니다 — `polyline`만 남습니다.)

## 1. 숫자만 정하면 되는 것 (5종) — 가장 쉬움

### 1-1. 장기간 러닝 성공
- 시안 문구: "3시간 넘게 런트립"
- 제안: `durationSeconds > 3시간` (한 번의 러닝 기준)
- **[답]**: 제안대로 해

### 1-2. 완주 10회 달성
- 시안 문구: "완주 10회"
- 확인 필요: **"완주"가 공식 코스 완주만인지, 자유 러닝 포함 모든 기록인지.**
- 제안: 저장된 러닝 기록 **10건**(자유 러닝 포함, `courseId` 무관)
- **[답]**: 자유 러닝까지 포함

### 1-3. 100km 이상
- 시안 문구: "누적거리 달성"
- 제안: 모든 러닝의 `distanceMeters` 합계 **100,000m 이상**
- **[답]**: 응 진짜 모든 러닝의 합계 100KM야

### 1-4. 얼리버드
- 시안 문구: "아침 8시 이전에 런트립 시작"
- 제안: `startedAt`이 **한국시간(KST) 08:00 이전**
- 참고: 서버는 시각을 UTC로 저장합니다. KST 기준이 맞다고 보는데, 확인해주세요.
- **[답]**: 이거 서버 시작 시간 한국시간으로 바꿔줘. 그려면서 한국시간 기준 8시 이전으로 해, 그리고 오전12시(밤 12시 - 다음날로 넘어가는 기준 시간)부터 8시 이전 기준으로 잡아줘

### 1-5. 아이스크림 러너
- 시안 문구: "12월 중 런트립 완주"
- 제안: `finishedAt`이 **한국시간 기준 12월**이면 달성 (연도 무관, 매년 12월마다 가능 — 단 **최초 1회만** 도장)
- **[답]**: 한국시간 기준 12월

### 1-6. 뚜벅이 ⚠️ 시안에 숫자가 없음
- 시안 문구: "완주시 페이스가 키로당 **몇 분**" ← 이 부분이 비어 있습니다
- 참고: 이름이 "뚜벅이"라 **느린 페이스**를 칭찬하는 업적으로 보입니다(빠른 게 아니라).
  그렇다면 `averagePaceSeconds >= 기준` 이 됩니다.
- 제안: **키로당 9분(540초) 이상**이면 달성
- **[답]** (몇 분, 그리고 이상/이하 중 무엇): 우선 뚜벅이는 생성 하지마. 나중에 추가할 수 있게만 해

## 2. 판정 방식을 정해야 하는 것 (4종)

### 2-1. 경유지 3개 지나감
- 시안 문구: "경유지 3개 거치고 완주"
- 문제: 사용자가 만든 코스의 경유지 수를 서버가 모릅니다.
- 선택지:
  - **(A)** 공식 코스 중 **경유지 3개 이상**인 코스를 완주하면 달성
    → 해당 코스: 근대 역사 박물관 런(7개), 짬뽕런(4개), 선유도 해변 런(3개)
  - **(B)** 앱이 `POST /runs` 에 `waypointCount` 를 같이 보내주면 그 값으로 판정 (프론트 작업 필요)
  - **(C)** 보류
- **[답]** (A / B / C): 우선은 A로 해줘

### 2-2. 개척자
- 시안 문구: "새로운 코스를 만들어 런트립"
- 제안: **`courseId`가 `null`인 러닝**(= 공식 코스가 아닌 직접 만든 경로)을 저장하면 달성
- 참고: 이 방식이면 프론트 작업 없이 바로 됩니다. 다만 "자유 러닝"과 "코스를 만들어 달림"을
  구분하지 않습니다. 구분이 필요하면 앱이 플래그를 보내야 합니다.
- **[답]**: 어차피 우리는 자유러닝이 없을꺼야 그래서 그냥 코스ID가 없는 러닝이면 달성하는거로해

### 2-3. 휴식타임
- 시안 문구: "카페, 음식점을 도착지로 설정하고 러닝 완주"
- 문제: 서버는 **도착지로 어떤 장소를 골랐는지 모릅니다.** 현재 판정 불가입니다.
- 선택지:
  - **(A)** 앱이 `POST /runs` 에 도착지 장소 id 또는 카테고리를 같이 보냄 (프론트 작업 필요)
    → 예: `"destinationCategory": "CAFE"` 또는 `"destinationPlaceId": "1305903"`
  - **(B)** 보류
- **[답]** (A / B, A면 어떤 형태로 보낼지): B, 우선은 만들지마 이건 결정나면 말해줄께

### 2-4. 방문형 3종 — 천변벚꽃 / 덕진 호수 / 전주 자연생태관
- 시안 문구: "삼천천 벚꽃길 방문", "덕진호수의 연꽃들 관람", "전주 자연생태관 방문"
- 문제: **"방문"을 판정할 수단이 없습니다.** 해당 장소를 지나는 공식 코스도 없습니다.
- 선택지:
  - **(A)** 러닝 `polyline`이 해당 장소 좌표 **N미터 이내**를 지나면 달성
    → 좌표와 반경을 주셔야 합니다 (예: 덕진호수 35.8xx, 127.1xx / 반경 150m)
  - **(B)** 해당 장소를 지나는 **공식 코스를 새로 추가**하고, 그 코스 완주로 판정
  - **(C)** 보류
- **[답]** (A / B / C, A면 세 곳의 좌표와 반경): C 우선 이것도 보류 만들지 말아봐

## 4. 도장 이미지

서버는 업적의 `code`(예: `JJAMPPONG`)만 내려줍니다. 시안 스크린샷은 있지만 **개별 이미지 파일은 없습니다.**

- 선택지:
  - **(A)** 프론트가 `code`로 앱 내장 이미지를 매칭 (서버 작업 없음)
  - **(B)** 서버가 이미지를 서빙 — 코스 이미지처럼 `/images/achievements/{code}.png`
    → 21개 PNG 파일을 주시면 배치하고 응답에 `imageUrl` 추가하겠습니다
  - **[답]** (A / B): A로

## 5. TourAPI 서비스키 (별건 — 영업시간 기능 관련)

어제 목록 영업시간 작업 중 **일일 호출 한도를 테스트만으로 소진**했습니다. 캐시 TTL을 24시간으로
늘려 호출량을 크게 줄였지만, 계정 종류에 따라 추가 조치가 필요할 수 있습니다.

### 5-1. 운영 서비스키가 개발계정인가요, 운영계정인가요?
- 공공데이터포털 마이페이지 > 오픈API > 활용신청 상세에서 **일일 트래픽**을 볼 수 있습니다.
- **[답]** (계정 종류 / 일일 트래픽 숫자): 개발 계정 / 트래픽은 나중에 줄께

### 5-2. 초당 한도
- 실측: **25 req/s를 지속하면 초당 한도 초과**가 발생했습니다. 현재 **10 req/s**로 낮춰 뒀지만
  이 값은 검증하지 못했습니다(일일 한도가 먼저 소진돼서).
- 한도가 리셋되면 안전한 값을 다시 측정하겠습니다. 별도 입력은 필요 없고, 위 5-1만 알려주시면 됩니다.
