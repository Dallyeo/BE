# 배지 데이터(모범음식점 / 착한가격업소) 분석 — 군산시

> **목적**: 파일데이터를 TourAPI 장소에 **배지(badge)**로 병합하기 위한 구조/매칭 분석.
> **대상 배지**: `MODEL_RESTAURANT`(모범음식점), `GOOD_PRICE`(착한가격업소)

---

## 1. 파일 현황

| 파일 | 인코딩 | 데이터 건수 | 컬럼 |
|---|---|---|---|
| `전북특별자치도 군산시_모범음식점_20260130.csv` | **UTF-8** | 52 | 연번, 업소명, 소재지, 연락처, 음식종류 |
| `전북특별자치도 군산시_착한가격업소 현황_20260416.csv` | **EUC-KR** | 60 | 연번, 업종, 업소명, 주소(도로명) |

> ⚠️ 착한가격업소 CSV는 **EUC-KR** → 적재 시 UTF-8 변환 필요. 모범음식점은 UTF-8.

### 착한가격업소 업종 분포 (60건)
`한식_일반 26 / 미용업 12 / 한식_육류 8 / 중식 5 / 기타요식업 3 / 양식 2 / 목욕업 2 / 일식 1 / 이용업 1`
- **비음식(미용/목욕/이용) 15건**은 우리 앱 장소(음식점/카페) 배지 대상 아님 → 적재 시 요식업만 필터 or 전체 적재 후 매칭 안 되면 자연 제외.

---

## 2. ⚠️ 핵심: 매칭 키 재검토 (`lcnsno` 사용 불가)

TourAPI 음식점 `detailIntro2`에는 `lcnsno`(인허가번호)가 있어 정확 매칭 키 후보였으나,
**두 CSV 모두 인허가번호·좌표(위경도)가 없음.** 보유 필드는 **업소명 + 도로명 주소**뿐.

→ 매칭은 **업소명 + 주소 텍스트 정규화 비교**로만 가능.

### 매칭 난점
- 주소 형식 차이: TourAPI `전북특별자치도 군산시 경촌4길 14` vs CSV `... 대학로 649 (신관동)` — 공백/괄호(동명)/번지 표기 상이
- 업소명 표기 차이: `바다회집현대코아점`, 지점명 포함 등
- 완전 자동 정확 매칭은 어려움

### 매칭 전략 후보
| 방식 | 설명 | 장단점 |
|---|---|---|
| A. 정규화 + 정확일치 | 업소명·주소 공백/괄호/특수문자 제거 후 exact match | 간단하나 미스율↑ |
| B. 정규화 + 부분/유사일치 | 도로명+건물번호 파싱 + 업소명 fuzzy | 재현율↑, 오매칭 리스크 |
| C. 수동 매핑 테이블 | 52+60건으로 적어 사람이 1회 매핑표 작성 | 정확·안정, 갱신 시 수작업 |
| D. 하이브리드 | 자동(B)으로 후보 → 애매한 것만 수동 확정 | 균형적, 권장 후보 |

> **데이터가 소량(도합 112건)** 이므로 C 또는 D가 현실적. 정기 갱신 주기(파일 재배포)도 낮음(연 단위 파일명).

---

## 3. 배지 모델 (제안)

- 장소 응답 `badges: string[]` — 값: `MODEL_RESTAURANT`, `GOOD_PRICE`
- 적재 방식: CSV → 배지 테이블(`업소명`, `주소정규화`, `배지타입`) 적재 → TourAPI 장소 조회 시 매칭하여 부여
- 미매칭/미적재 시 빈 배열

---

## 4. 결정 (✅ 확정)
1. **매칭 전략**: ✅ **D 하이브리드** — 업소명+주소 정규화 자동 후보 → 애매한 건만 수동 확정.
2. **착한가격업소 비음식 15건**: ✅ **요식업만 적재** (미용/목욕/이용업 제외).
3. **갱신 방식**: 소량(≤112건)이라 파일 재업로드 시 **수동 재적재**로 충분 (자동 파이프라인 불필요).
4. **지역 확장(미결)**: 현재 군산만. 전주 배지 CSV는 추후 확보 필요.
